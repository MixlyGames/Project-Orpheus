# Проект: свой UI для LLM с аватаром

Личный проект, только Windows, не для коммерции и не для публикации.

Рабочее название в интерфейсе: **Orpheus** (окно называется «Project Orpheus»). Внутри проекта оно пока называется **mebius** (пакет npm, крейт Rust, идентификатор `com.mixlygames.mebius`).

Последнее обновление файла: 10.11.2026.

## Идея
Что-то вроде Claude Desktop, но со своим дизайном, названиями и механиками:
- чат-интерфейс для LLM (API-провайдеры и локальные модели);
- 3D-рендерер для аватара (предварительно: Three.js + VRM);
- 2D-режим: пиксельная или рисованная анимация через спрайтшиты (PixiJS), без Live2D;
- питомец/аватар на рабочем столе, живёт независимо от главного окна (схема ещё не выбрана, см. ниже);
- TTS и STT: и через API (например ElevenLabs), и локально через ONNX;
- позже: работа с программами на компьютере и игра в кооп-игры вторым игроком.

Акцент проекта: чат, аватар и настройка под себя. Информационные виджеты (время, погода) на главном экране сознательно не делаем.

## Стек
- Tauri 2 + Rust (edition 2024). Rust-часть пока шаблонная: плагин `opener` и учебная команда `greet`, своих команд нет.
- Vite 8 + TypeScript 6, фронтенд на чистом TS без фреймворка (переход на React не подтверждён).
- Шрифты: Golos Text и JetBrains Mono (`@fontsource-variable`).
- Установлены, но ещё не используются в коде: `three`, `@pixiv/three-vrm`.
- Платформа: только Windows (WebView2). Окно без системной рамки (`decorations: false`), свой заголовок с кнопками окна.
- CSP в `tauri.conf.json` сейчас отключён (`null`), поэтому `blob:`-ссылки для фона работают.

### Хранение данных (локально)
- `localStorage`: `orpheus.profile` (профиль), `orpheus.settings` (настройки), `orpheus.chats` (чаты).
- IndexedDB `orpheus.media`: файлы фона (картинка и видео).

## Что уже есть (на 10.11.2026)

**Знакомство.** Шаги: приветствие, имя, «о себе», готово. Профиль хранится локально. Если профиль уже есть, знакомство пропускается и сразу открывается чат.

**Главный экран.** Панель кнопок («dock») слева (вертикально) или сверху (горизонтально), с подписями или без, с анимированной «каплей» под активной кнопкой. Разделы на панели: Чат, История, Управление, Настройки, Дебаггер. «Аватар» открывается карточкой в «Управлении» (кнопка «Назад» и Esc возвращают), на панели при этом подсвечено «Управление». Горячие клавиши: Ctrl + 1…5. При ширине окна до 880 px подписи на верхней панели скрываются, чтобы кнопки не наезжали на кнопки окна.

**Чат.** Отвечает провайдер, выбранный в настройках (интерфейс `LLMProvider.stream`): заглушка `fakeProvider` (печатает ответ по буквам, работает без сервера) или Орфея (Python-сервер по WebSocket, см. «Наметки по архитектуре»). Если сервер недоступен, в чате показывается понятная ошибка. Есть потоковый вывод, остановка генерации, новый чат, копирование сообщений, стартовые подсказки, приветствие по времени суток. Окошко Орфеи справа внизу пока заглушка (звезда), показывается только при ширине раздела от ~1290 px. Кнопка «Новый чат» отодвинута от правого края, чтобы не оказаться под кнопками окна.

**Лента поиска над ответом Орфеи.** Если Орфея вызывает поиск, над её ответом появляется сворачиваемый блок. Пока идёт поиск: «Ищу в интернете…» с пульсирующей точкой. Потом: «Поиск в интернете · N источников» (при нескольких попытках ещё «попыток: N», при заметном времени ещё секунды). Внутри лента шагов: запрос, результат («N источников» или причина неудачи жёлтым цветом) и строки источников (иконка сайта, заголовок, домен). Клик по источнику открывает ссылку в обычном браузере (плагин `opener`, только `http(s)`). Когда пошёл текст ответа, блок сворачивается сам, если пользователь не раскрывал и не закрывал его вручную. Если инструменты не вызывались, блока нет. Шаги сохраняются вместе с сообщением (`trace`, `traceMs`), после перезапуска блок остаётся свёрнутым. Надписи «Размышление» нет: у Орфеи CoT выключен. Тексты из выдачи выводятся только через `textContent`. Иконки сайтов берутся с `icons.duckduckgo.com`, при ошибке остаётся первая буква домена.

**История.** Поиск по чатам, открытие, удаление.

**Аватар** (открывается карточкой в «Управлении»). Переключатель «3D · VRM / 2D · Спрайты» (выбор запоминается). В режиме 3D кнопка «Выбрать VRM…» загружает файл `.vrm` (версии 0.x и 1.0, до 200 МБ, проверяется сигнатура glTF), и модель рисуется в предпросмотре (`three` и `three-vrm`): руки опущены из T-позы, лёгкое дыхание и моргание. Мышь: перетаскивание поворачивает, Ctrl + колесо масштабирует, двойной клик сбрасывает. Файл сохраняется в IndexedDB (`orpheus.avatar`) и поднимается при первом открытии раздела, кнопка «Убрать» удаляет. Отрисовка идёт только пока раздел открыт и выбран режим 3D. Режим 2D пока заглушка (строки «Параметры спрайтшита» и «Анимации»). Анимации, выражения и связь с Орфеей ещё не подключены. Поза рук: `ARM_DOWN` в `engine.ts` (0 это T-поза, 1 это А-поза; значение и знак подобраны вручную на одной модели, на модели другой версии VRM ещё не проверены).

**Управление.** Карточки модулей: Модель (показывает активный провайдер), Голос, Слух, Аватар (открывает раздел «Аватар»), Питомец, Приложения, Игры. У остальных, кроме «Модели» и «Аватара», статус «Скоро».

**Настройки.**
- Профиль (изменить).
- Чат: кто отвечает (заглушка или Орфея).
- Интерфейс: положение панели, подписи к кнопкам.
- Оформление: тема (тёмная/светлая), анимации интерфейса, движение фона, фон (шёлк, своя картинка, своё видео), выбор и удаление файла, затемнение фона.
- Данные: очистка истории (двухшаговая).
- О приложении.

**Дебаггер** (пятая вкладка, Ctrl + 5). Единый журнал приложения с понятным текстом от трёх источников: «Система», «Чат», «Орфея». Фильтры по источнику и по важности («Проблемы»), копирование и очистка. Переключатель «Режим разработчика» добавляет технические детали (стеки, адреса), точное время и отладочные записи. В журнал попадают запуск приложения, смена провайдера, загрузка и удаление модели аватара, отправка и получение ответов, остановка, ошибки, необработанные сбои интерфейса и события сервера Орфеи (сообщения `log`). Журнал хранится только в памяти (последние 500 записей) и очищается при перезапуске.

**Фон.** По умолчанию WebGL-шейдер «шёлк» в половинном разрешении, цвета зависят от темы. Своя картинка (до 30 МБ) или видео (до 300 МБ, MP4 H.264 или WebM). Если файл не открылся, возвращается шёлк. Анимации можно отключить: учитывается и настройка в приложении, и системная `prefers-reduced-motion`.

## Структура кода
- `index.html`: разметка всех разделов.
- `src/main.ts`: знакомство, кнопки окна, запуск.
- `src/chat.ts`: чат.
- `src/shell.ts`: разделы, панель кнопок, история, настройки, аватар.
- `src/llm.ts`: интерфейс `LLMProvider`, заглушка, провайдер Орфеи (WebSocket) и `providerFor`.
- `src/store.ts`: хранилище чатов.
- `src/settings.ts`: настройки (тема, режим аватара, провайдер, режим разработчика).
- `src/log.ts`: единый журнал (`log(источник, уровень, текст, детали)`), перехват необработанных ошибок.
- `src/debug.ts`: вкладка «Дебаггер» (лента, фильтры, копирование, режим разработчика).
- `src/trace.ts`, `src/trace.css`: лента шагов поиска над ответом Орфеи (запросы, источники с иконками, неудачные попытки).
- `src/avatar/`: движок аватара. `engine.ts` (сцена, камера, загрузка VRM, цикл отрисовки, дыхание и моргание), `store.ts` (выбранная модель в IndexedDB), `view.ts` (страница «Аватар»: предпросмотр, выбор файла, тексты), `avatar.css`.
- `src/background.ts`, `src/media.ts`: фон и пользовательские файлы фона.
- `src/styles.css`, `onboarding.css`, `shell.css`, `chat.css`: стили (тема через CSS-переменные и `data-theme` на `<html>`).

### Соглашения
- Тема: `--fg-rgb` и другие переменные в `:root`, светлая включается через `data-theme="light"`.
- Анимации через WAAPI (`element.animate`) нужно проверять через `motionReduced()` из `settings.ts`: CSS-правило `body.no-motion` на них не действует.
- Настройки читаются и меняются только через `getSettings()` / `updateSettings()` / `onSettings()`.

## Наметки по архитектуре (обсуждалось, ещё не решено и не реализовано)

**Провайдеры.** Одинаковый подход для LLM (уже есть), TTS, STT и инструментов: интерфейс плюс подменяемые реализации.

**Орфея (Python), сделано, 11.11.2026.** Живёт в PyCharm-проекте `Orpheus` (`C:\Users\MixlyGames\PycharmProjects\Orpheus`; папка `mebius` лежит внутри него отдельным репозиторием). Там уже есть: дообученная локальная модель `orphea-merged-tools` (4 бита, CUDA, transformers), `memory.py` (ChromaDB), `hands.py`, `vision.py`, `reflect.py`, `relations.py`, голос `Head/voice_orpheus.py` и Discord-бот `bot_chat.py`.
- Для приложения написан `orphea_server.py`: FastAPI + WebSocket `ws://127.0.0.1:8765/chat`, только localhost, проверка заголовка Origin (разрешены адреса Tauri и dev-сервера Vite). `GET /health` показывает, что сервер жив.
- Протокол JSON. Клиент шлёт `{"type":"chat","id","messages":[{role,content}]}` и `{"type":"stop"}`. Сервер шлёт `ready`, `token`, `done` (с признаком `stopped`), `error`, а также `log` (`level`, `message`, `details`): события для вкладки «Дебаггер» (начала отвечать, ответ готов за N секунд, нет системного промпта, ошибки генерации).
- История приходит от приложения (последние 12 реплик). Системный промпт сервер берёт из `dataset.json` или `orphea_minds_main.json` рядом с файлом, либо по пути из переменной `ORPHEA_DATASET`.
- Не запускать одновременно с `bot_chat.py`, если не хватает видеопамяти на две копии модели.
- «Руки» (12.11.2026): сервер подключает `hands.py`. Если ответ Орфеи начинается с `<tool_call>`, сервер молча выполняет инструмент (пока только `web_search`, чтение из DuckDuckGo), отдаёт результат модели и просит ответить снова, не больше `MAX_TOOL_STEPS` раз. На просьбы вроде «найди…» история не подмешивается и добавляется `TOOL_HINT`, как в `bot_chat.py`. Если `hands.py` не загрузится, сервер работает как обычный чат.
- Событие `step` (лента поиска в чате): `{"type":"step","id","step_id","kind":"search","status":"running|done|failed","query","sources":[{title,url,snippet}],"code","reason"}`. Повтор с тем же `step_id` обновляет шаг. Коды неудачи: `empty` («Ничего не нашлось»), `timeout` («Поиск не ответил вовремя»), `bad_call` («Не удалось разобрать вызов поиска»), `error` («Поиск сломался»). В источниках только те выдержки, которые реально получила модель.
- `hands.web_search_structured(query)` возвращает `(текст_для_модели, источники, код)`. Старый `web_search` вызывает её и отдаёт только текст, поэтому Discord-бот работает как раньше.
- Для дообучения (позже): диалоги, где поиск вернул пусто, ошибку или нерелевантное, а Орфея честно об этом говорит и предлагает переформулировать; примеры повторной попытки с другим запросом; примеры, где поиск не нужен. Результаты инструмента оформлять так же, как их делает `hands.wrap_result`. Исходник для примеров: «Дебаггер» (кнопка «Копировать»).
- Фронтенд: `orpheaProvider` в `llm.ts`, выбор в Настройки → Чат (по умолчанию заглушка, чтобы приложение работало без сервера).

**Другие внешние части** (мод игры, процесс-питомец): тот же подход, локальный WebSocket. Если запросы из фронтенда на localhost упрутся в CORS, ходить через Rust. Альтернативы для LLM, если понадобятся: готовые серверы (Ollama, LM Studio, llama.cpp server) или всё на Rust.

**Аватар (решения от 14.11.2026).**
- Один движок аватара (`src/avatar/`): принимает холст и события и не знает, где стоит (раздел «Аватар», окно на рабочем столе). Два режима внешности, 3D (VRM, `three` и `three-vrm`) и 2D (спрайтшиты), реализуют один интерфейс `Avatar`; переключение режима меняет только внешность внутри того же процесса.
- Модель управляется не координатами, а намерениями: событиями «речь», «эмоция», «действие». Контроллер превращает их в анимации, липсинк и движение.
- Раздел «Аватар» открывается карточкой в «Управлении» (на панели кнопок его нет).
- Студия (анимации, аксессуары и так далее) делается как плагин `.orph` с кодом. Пока плагины только свои, код доверенный, песочница и разрешения не нужны. Модель остаётся обычным `.vrm`; закрытый формат с шифрованием отложен. Когда Студия устоится, часть её возможностей упростят и вынесут в вкладку «Аватар».
- Анимации берём из Mixamo (FBX) с перенацеливанием на скелет VRM. Версию VRM (0.x или 1.0) определяем при загрузке, а не прошиваем в код; своя шкала выражений, адаптер переводит под конкретную модель.

**Липсинк.** Начать с громкости (Web Audio `AnalyserNode`), позже виземы. Для 2D в спрайтшите сразу закладывать кадры рта. Липсинк должен быть рядом с воспроизведением звука, поэтому TTS-интерфейс отдаёт не только звук, но и события.

**Питомец (решение от 14.11.2026).** Орфея живёт внутри самого приложения: один процесс, один движок аватара. 2D (спрайтшиты) и 3D (VRM) это два режима внешности, они переключаются внутри того же процесса без перезапуска. Она должна оставаться на рабочем столе, когда главное окно свёрнуто или перекрыто другой программой. Техническая оговорка: свёрнутое окно система не рисует, поэтому поверхностью, которая видна независимо от главного окна, будет прозрачное окно того же Tauri-приложения (тот же процесс и то же ядро на Rust, а не отдельная программа). Заметки, которые нужно проверить на своей версии Tauri:
- окно прозрачное, без рамки, поверх остальных, без кнопки на панели задач, клики сквозь пустые места (`setIgnoreCursorEvents` плюс опрос курсора через Rust);
- не делать окно дочерним (`parent`), иначе оно может скрываться вместе с главным;
- перехват закрытия главного окна (прятать, а не завершать приложение), возможно трей;
- у каждого окна свой WebView: связь с сервером Орфеи и логику питомца держать в Rust или в самом окне питомца.

**Формат спрайтшита (предложение, не утверждено).** Сетка одинаковых кадров в PNG плюс JSON с размером кадра, числом кадров и FPS для каждого состояния (покой, речь, раздумье) и кадрами рта.

**Игры.** Идея: мод внутри игры добавляет персонажа как второго игрока и общается с приложением по локальному каналу. Состояние мира идёт текстом, команды идут обратно. Только игры без античита. Под каждую игру отдельный адаптер.

## Идеи для отличия от похожих проектов

- Голосовой режим с орбом-визуализатором.

## Правила работы с ИИ
- Перед крупными правками делать коммит в git. Автор git пока не настроен (`user.name`, `user.email`), поэтому коммитит пользователь.
- Не заходить в `node_modules/` и `target/`.
- Не читать `.env` и любые ключи/секреты.
- Изменения в `src-tauri/tauri.conf.json` и `capabilities/` проверять вручную.
- Сборку и запуск (`npm run tauri dev`, `cargo`) делает пользователь, ошибки присылает или они видны через диагностику.
- Терминал в VS Code это PowerShell: нет `&&` (использовать `;`), git вызывать с `--no-pager`, иначе терминал зависает в `less`. Таймаут команд по умолчанию 10 секунд.
